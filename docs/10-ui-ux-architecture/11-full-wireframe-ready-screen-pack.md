# 1. Purpose

This document closes the wireframe-ready screen-pack gap by defining the full grouped screen pack needed for provider, org-admin, and HRMS business flows.

# 2. Screen Families

Required wireframe-ready families:

- provider control plane
- org admin setup
- people and employee profile
- recruitment and offers
- attendance and leave
- payroll control
- documents and signatures
- audit and security
- implementation, QA, and support operations

# 3. Wireframe-Ready Definition Standard

Every screen definition should include:

- page goal
- primary actors
- sections and cards
- key states
- actions
- validation cues
- dependencies
- mobile and responsive notes

# 4. Completion Rule

The wireframe-ready pack is considered complete when every screen family above has:

- entry screen
- list or workbench
- detail or drill-down view
- exception or error state
- empty state
- permission-denied state
