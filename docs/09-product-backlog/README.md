# Product Backlog

This section converts the Enterprise HRMS specification repository into a structured delivery backlog that product, engineering, design, QA, implementation, and leadership teams can execute against.

Documents:

- `01-backlog-operating-model.md`
- `02-release-slicing-and-priority-waves.md`
- `03-epic-register.md`
- `04-module-feature-breakdown.md`
- `05-story-and-task-decomposition.md`

Recommended usage:

- Product managers: start with `02-release-slicing-and-priority-waves.md` and `03-epic-register.md`
- Engineering leads and architects: start with `03-epic-register.md` and `04-module-feature-breakdown.md`
- Designers: use `02-release-slicing-and-priority-waves.md` and `04-module-feature-breakdown.md`
- QA leads: use `03-epic-register.md` and `04-module-feature-breakdown.md` together with module specs and deep specs
- Implementation teams: use `02-release-slicing-and-priority-waves.md` for rollout planning and `04-module-feature-breakdown.md` for cutover scoping

Backlog hierarchy:

- Initiative
- Epic
- Feature group
- User story
- Task

Scope note:

- The backlog in this section is derived from the completed module and deep sub-module specification library
- The backlog is intentionally product-oriented rather than ticket-tool-specific
- Story-level decomposition now exists and should be extended sprint by sprint from the epic and feature-group structure defined here
